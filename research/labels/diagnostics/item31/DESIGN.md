## 5. Stage-1 criterion — STRUCTURE (committed before the census ran)

**Population.** Option A (the default of this design) is **T = the 16 TEST
series of the original split** whose labels are usable: series hash matches and
the schema is current. Let *n* be their number.

Option B adds the 3 batch TEST series. That is **Danilo's decision**, and it
needs new evaluator code, since the evaluator has only `--batch-train`.

**Labels.** `current` is primary. `first-blind` is scored in the same execution.
**PASS must hold under both versions.** If they give different verdicts, the
result is recorded as FAIL (not robust), with both sets of numbers.

**Comparators.** All three run in **one execution** of one script at one
commit:

* **P15**: `research/labels/configs/cyclophaser_params-15.yaml` via
  `evaluate_against_labels.load_config`, as a file.
* **DEF**: the package defaults at that commit. The run asserts that the front_b
  default digest is still `b500d2e0…`, so DEF is the current default behaviour
  and not a moved one.
* **CONST**: ignores the series. It uses the modal TRAIN sequence
  S\* = `intensification > mature > decay` and the incipient answer INC\* = "no
  incipient phase". It is frozen in `constant_train.txt`, derived from the 35
  real TRAIN labels (14/35 carry S\*, against 13/35 for the runner-up, so there
  is no tie). The current and first-blind versions give the same S\* and INC\*.

**Metrics.** Each is a count, on the evaluator's ruler (`labels_core.score_labels`
and `score_phase_sequences`, called as `evaluate_against_labels.py` calls them).

| symbol | what | denominator |
|---|---|---|
| H(x) | incipient boundary hits: \|detected end − label end\| ≤ that label's own `tolerance_idx`; a refusal on a boundary label is a miss | B = labels with verdict `boundary` |
| R(x) | refusal agreement: the label says "no incipient" and x produces none | N₀ = labels with verdict `none` |
| C(x) = H + R | incipient decisions correct | B + N₀ (ambiguous excluded, counted aside) |
| Q(x) | full phase sequence equal to the label's | n |
| MAT(x) | first labelled mature paired by `item19_core.pair_by_overlap`, both ends within 6 | M = labels with ≥ 1 mature |

**Reported, outside the verdict:**

* false refusals, meaning boundary labels on which x refuses;
* ambiguous labels on which x refuses;
* discordant pairs P15 vs DEF for C and Q (series where P15 is right and DEF
  wrong, and the reverse);
* the evaluator's per-phase boundary numbers.

**Mature instrument: `pair_by_overlap`, not the evaluator.** The evaluator scores
mature boundaries only on series whose whole sequence matched, so its
denominator is set by each comparator's own sequence hits. The P15 and DEF
numbers would then be counted over different populations. `pair_by_overlap`
scores every label that has a mature, with the same denominator M for both. It
is the Benchmark's `MATURE_INSTRUMENT` (margin 6), used as a frozen instrument.
CONST has no block positions, so it takes no part in the mature comparison.

**Verdict — PASS if and only if every condition holds.** Otherwise FAIL, and
the record names each failed condition.

| | condition | reads |
|---|---|---|
| V1 | C(P15) > C(DEF) | better incipient decisions than the current default |
| V2 | Q(P15) > Q(DEF) | better full sequences than the current default |
| V3 | C(P15) > C(CONST) = N₀ | the detector beats "always refuse" (because INC\* = none, H(CONST) = 0 and R(CONST) = N₀) |
| V4 | Q(P15) > Q(CONST) = K\* | the detector beats "always S\*" (K\* = labels whose sequence is S\*) |
| V5 | MAT(P15) ≥ MAT(DEF) | no mature regression against the current default (a tie passes) |

**Declared consequence of the constant.** Both of CONST's scores on TEST, N₀ and
K\*, are functions of the labels alone. The census in §4 therefore fixes the
bars of V3 and V4 **before stage 1 runs**. That is part of the census's declared
exposure.

**Mechanical count, outside the verdict (not a comparator, no labels):** the
number of the 16 on which the final maps of params-14 and params-15 differ. It
reports whether TEST exercises `spare_intensification` at all (see §2).
Including params-14 as a scored comparator is part of the comparator-scope
decision left to Danilo.

**Reachability.** This section is completed with the census numbers below the
line. The conditions required are:

* PASS needs B ≥ 1 (for V3), K\* ≤ n − 1 (for V4), n ≥ 1 and B + N₀ ≥ 1.
* FAIL is reachable for any counts, since a tie on V1 or V2 already fails.
* V5 is vacuous if M = 0, and that would be said.

With the census: B = 9 ≥ 1, K\* = 5 ≤ 15, n = 16 ≥ 1, B + N₀ = 15 ≥ 1 and
M = 15 > 0. Every condition holds.

## 7. Default filtering — proposal

**Recommendation: ship params-15's filter with its phase parameters.**

* `use_filter='auto'` (unchanged; it is ≡ `True` without the warning);
* `cutoff_low = 168` (unchanged);
* `cutoff_high = 18.0` (currently 48.0);
* `use_smoothing = False` and `use_smoothing_twice = False` (currently
  `'auto'`);
* `savgol_polynomial = 3` and `replace_endpoints_with_lowpass = 0` (unchanged);
* `boundary_padding = 'edge'` (currently `'reflect'`);
* **no presets API**.

**Justification, with what argues against it.**

1. **params-15 is one calibrated object.** Every phase parameter from items 19
   to 30 was chosen and scored under this filter. The phase thresholds are
   relative to the filtered series (`length_scale='local'`, amplitude
   fractions, depth floors). A phase-only default change would ship a
   combination no front ever calibrated.
2. **The hybrid was measured here, on TRAIN only** (`constant_train.txt`,
   `p15-phase|def-filter`):

   | | incipient | sequence | mature |
   |---|---|---|---|
   | hybrid | identical (22/33) | **22/35** | **20/33** |
   | params-15 | 22/33 | 19/35 | 27/33 |

   The incipient scores are identical because the plateau signal reads the
   unfiltered vorticity. **The params-15 filter is therefore not dominant.** It
   costs 3 sequences and gains 7 matures on the 35. Recommending the hybrid on
   the strength of this row would be a choice made after seeing TRAIN numbers,
   with no declared premise. The recommendation stays with the calibrated
   object. The trade-off is recorded as an **open question for Danilo**; if it
   is pursued, it needs its own front. **Decided (§8.4): params-15's filtering;
   the hybrid is parked.**
3. **No presets.** A preset API multiplies the configurations to validate,
   document and keep equivalent (EQ-style gates per preset). The research
   configs already live as versioned YAML in `research/labels/configs/`, and a
   user who wants the old behaviour passes arguments (EQ4 guarantees that path).
4. **`use_filter='auto'`, not `True`.** The two are equivalent, and `'auto'`
   avoids a warning on every default call.
