# 4. CI — read from `.circleci/config.yml` @ develop-v2.1 `76b7932`

`.circleci/config.yml` is the only CI file in the repository. There is no
`.github/workflows/`, `.gitlab-ci.yml`, `tox.ini`, `noxfile.py` or `.travis.yml`.
CircleCI's project settings, including the values of its environment variables,
cannot be seen from the repository, so they are not reported here.

One workflow, `build_test_publish`, with three jobs:

| job | trigger (branch filter) | image / Python | steps | publishes to |
|---|---|---|---|---|
| `build_test` | **every push, every branch** (no filter) | `cimg/python:3.12.3` (Python 3.12 only) | `pip install --upgrade pip build`; `python -m build`; `pip install dist/*.whl`; `pip install pytest pyyaml`; `python -m pytest --junitxml=test-reports/results.xml` | nothing |
| `test_pypi_publish` | `requires: build_test`; **only branch `develop`** | `cimg/python:3.12.3` | `pip install --upgrade pip build "twine>=6.0"`; `python -m build`; `twine check dist/*`; `twine upload --skip-existing -u ${TESTPY_LOGIN} -p ${TESTPY_PASSWORD} --repository testpypi dist/* --verbose` | **TestPyPI** |
| `pypi_publish` | `requires: build_test`; **only branch `master`** | `cimg/python:3.12.3` | same build + `twine check`; `twine upload --skip-existing dist/* --verbose` | **PyPI** |

## Authentication (mechanism only, no values)

* **TestPyPI:** a username and password passed explicitly to twine (`-u`/`-p`) from two
  CircleCI project environment variables, `TESTPY_LOGIN` and `TESTPY_PASSWORD`. This is a
  token or credential held in a CI secret.
* **PyPI:** no credential appears on the command line. `twine` is called with neither
  `-u`/`-p` nor `--config-file`, so it falls back to the `TWINE_USERNAME`/`TWINE_PASSWORD`
  environment variables (CircleCI project settings) or to a `~/.pypirc` in the
  container's home. This is again a token or credential held in a CI secret. Whether
  those variables are set cannot be seen from the repository.
* **Not trusted publishing:** no OIDC step and no `id-token` exchange appear anywhere in
  the configuration.

## Facts relevant to a release (reported, not acted on)

1. **The TestPyPI job never runs now.** Its filter is branch `develop`, and there is no
   branch `develop` on the remote (the heads are `master`, `develop-v2.1` and
   `fix/relabel-recovery`). This is consistent with TestPyPI stopping at **1.9.4**:
   2.0.0 was never published there (`01_pypi_versions.txt`).
2. **Publishing to PyPI is automatic on any push to `master`**, after `build_test`
   passes, with whatever `VERSION` `setup.py` holds at that commit. Because of
   `--skip-existing`, a push to `master` that does not bump the version reaches PyPI
   **silently as a no-op**, not as an error.
3. **`build_test` covers Python 3.12 only** (see `07_python_requires.txt`).
4. **`build_test` runs the suite from the repository root with `python -m pytest`.**
   `python -m` puts the CWD first on `sys.path`, so the suite imports `cyclophaser/` from
   the checkout and **not** the wheel it just installed (see `05_import_mode.md`). The
   "Install package from wheel" step therefore checks only that the wheel installs. It
   does not check that the wheel works.
5. The only difference between master and develop-v2.1 in this file is that
   `build_test` installs `pyyaml` alongside `pytest`. That difference, plus its
   explanatory comment, is the whole diff.
6. `.pypirc` (a `[pypi]` username/password block) is still present in **`origin/master`'s
   tree** and in history since `e412b72` (2023-08-29). It was removed from the tree on
   develop by `c080f4d` (2026-09-28), whose message records that Danilo has already
   rotated the password and that history is not rewritten. The contents were not printed
   here; only their shape was checked (both fields non-empty).
